# 00. 프로젝트 헌장

## 1. 문서 목적

이 문서는 구린네의 미션, 이해관계자, 범위, 성공 기준, 금지선을 고정한다. 기능·기술·수익 압박이 생겨도 아래 원칙보다 우선할 수 없다.

## 2. 미션

대한민국 공공기관이 공개한 조달·계약·예산 정보를 시민이 이해하고 검증할 수 있도록 연결하고, 설명이 필요한 이상 징후를 체계적으로 찾아 **근거와 불확실성을 함께 공개**한다.

## 3. 비전

사람이 우연히 수천 장의 문서를 뒤져야 발견하던 패턴을, 공개 데이터와 재현 가능한 분석으로 전국 단위에서 지속적으로 점검한다. 시민·기자·연구자·감사 담당자는 구린네의 결론을 믿으라고 요구받지 않고, 원문과 계산을 직접 따라가며 판단할 수 있다.

## 4. 핵심 가치

### 4.1 Evidence first

먼저 원본, 그다음 추출값, 계산, 해석, 문장 순으로 간다. AI의 서술은 증거가 아니다.

### 4.2 Reproducibility

공개 수치는 입력 세트·단위 변환·규칙 버전으로 다시 계산할 수 있어야 한다.

### 4.3 Fairness to subjects

조사 대상도 오류가 없는 절차, 충분한 맥락, 소명권, 신속한 정정을 받을 권리가 있다.

### 4.4 Human accountability

공개 결정의 책임은 식별 가능한 사람에게 있다. 모델·알고리즘 뒤에 책임을 숨기지 않는다.

### 4.5 Independence

광고주, 고객, 후원자, 정당, 정부기관은 사건의 생성·우선순위·공개·정정 결과를 구매할 수 없다.

### 4.6 Security and restraint

공개되어 있다는 이유만으로 모든 정보를 모으거나 재배포하지 않는다. 개인정보, 제보자, 안보, 수사, 취약계층 위험을 최소화한다.

### 4.7 Correction over defensiveness

오류를 숨기지 않는다. 과거 문장을 지우기보다 정정 사유와 영향을 명확히 기록한다.

## 5. 제품 범위

### 5.1 포함

- 공식 OpenAPI, 파일, 공시 페이지의 수집
- 원본 응답·문서의 checksum과 metadata 보존
- 기관·업체·계약·품목·단위 정규화
- 가격·계약방식·반복·변경·시기·집중도 이상 신호
- 조사 case와 evidence graph
- 비교군, 계산, 제외 사유, 반대가설
- 기관·업체 소명 요청과 공개
- 편집·법률 검토와 immutable publication revisions
- 시민용 검색·피드·방법론·정정 페이지
- 기자·연구자용 API와 export(권한·라이선스 범위 내)
- source freshness, data quality, rule version 공개

### 5.2 첫 출시에서 제외

- 익명 제보 접수와 내부고발자 문서 저장
- 개인 단위 부패 프로파일
- 얼굴인식, 주민등록·가족관계 추적
- 비공개 데이터 매입
- 자동 수사의뢰나 고발장 제출
- 정당·선거 후보 점수
- 광고 기반 추천 피드
- 실시간 군사 운영·재고·시설 현황의 조합 분석

이 제외 항목은 영구 금지를 의미하지 않지만, 별도 법률·보안·제품 ADR 없이는 추가할 수 없다.

## 6. 핵심 사용자와 가치

### 시민

- 내 지역·기관이 어떤 계약을 했는지 이해
- “수상하다”는 감정 대신 원문·수치·설명을 확인
- 관심 기관·품목의 새 공개와 정정 알림

### 탐사보도 기자·시민단체

- 전국 데이터에서 조사 후보를 빠르게 찾음
- 원문과 계산을 재현하고 export
- 시간에 따른 업체·기관 계약 관계를 분석

### 공공기관 내부 감사·계약 담당

- 공개 전에 자체 이상 패턴을 발견
- 다른 기관의 유사 계약을 참고
- 오해가 생긴 사건에 공식 설명 제공

### 계약업체

- 자기 계약의 맥락과 구성요소를 설명
- 잘못된 업체 병합·단위·가격 비교 정정 요청

### 편집·조사팀

- 신호를 queue에서 triage
- evidence, unknown, counter-hypothesis를 구조적으로 관리
- 공개 전 정책·법률 게이트 확인

### 연구자·데이터 개발자

- 버전된 공공조달 정규화 데이터와 방법론 활용
- 결과 재현과 독립 검증

## 7. 제품 원칙에서 파생되는 설계 결정

| 원칙 | 설계 결과 |
|---|---|
| 증거 우선 | raw object + checksum, field-level provenance |
| 재현 가능 | deterministic RuleRun과 versioned cohort |
| 인간 책임 | human-only ReviewDecision and publication gate |
| 공정한 절차 | right-of-reply workflow와 correction SLA |
| 최소 공개 | public projection과 private editorial storage 분리 |
| 독립성 | billing/funder data가 detection pipeline에 들어가지 않음 |
| 보안 | untrusted content isolation, fetch allowlist, attachment sandbox |
| 투명성 | rule version, source lag, exclusions, limitations 공개 |

## 8. 성공 기준

### 8.1 신뢰성

- 공개 claim provenance coverage 100%
- publication gate bypass 0건
- fabricated citation 0건
- 공개 후 오류 정정 SLA 준수율 95% 이상
- 고위험 entity false merge 0건

### 8.2 분석 유용성

- 편집자가 “추가 조사 가치 있음”으로 판정한 signal 비율을 규칙별 측정
- gold eval에서 목표 precision/recall 달성
- 설명 가능성: 모든 signal이 자연어 이유와 계산 JSON을 제공
- false-positive 원인 taxonomy가 분기별 개선됨

### 8.3 운영

- source별 freshness SLO 표시
- raw replay로 parser 결과 재생 가능
- 백업 복구 drill 통과
- 비용 cap 위반 0건
- security incident 탐지·대응 연습 완료

### 8.4 공익

- 독립 검증·보도·연구에 사용된 공개 사례
- 기관 소명으로 오류 또는 맥락을 정정한 사례
- 공식 감사·제도 개선으로 이어진 사례
- 공개 방법론과 correction history 이용률

페이지뷰나 “적발 건수”만을 성공 기준으로 사용하지 않는다. 오탐을 많이 만든 뒤 자극적으로 배포하면 수치는 늘어도 미션에는 실패한다.

## 9. 윤리적 금지선

1. 무고한 사람을 클릭 유도용으로 실명화하지 않는다.
2. 데이터가 없는 기관을 낮은 위험으로 간주하지 않는다.
3. 특정 단체만 유리하게 임계값을 바꾸지 않는다.
4. 조사 대상에게 유료 삭제·정정·우선 답변 서비스를 팔지 않는다.
5. 제보자 신원을 제품 growth를 위해 수집하지 않는다.
6. 공개 문서의 개인 연락처를 검색 가능하게 재배포하지 않는다.
7. 모델 output을 “AI가 밝혀냈다”는 권위로 포장하지 않는다.
8. source가 삭제한 문서를 무조건 public mirror하지 않는다. 공익·라이선스·개인정보를 재검토한다.

## 10. 운영 주체의 책무

- 편집 정책과 방법론의 변경 이력 공개
- 주요 후원자·고객·이해상충 공개
- 외부 complaint와 correction 창구 운영
- 정기적인 독립 방법론·보안 검토
- 고위험 사건의 법률 검토 예산 확보
- 정치적 압력과 상업적 압력 기록
- 시스템의 오탐·누락·커버리지 한계를 명시

## 11. 브랜드와 편집 톤

“구린네”는 시민의 직관을 표현하는 브랜드일 수 있지만, 조사 문장은 절제되고 기술적이어야 한다. 헤드라인은 사실적 메트릭과 상태를 말하고, 비꼼·조롱·혐오·유죄 추정은 쓰지 않는다.

권장 태그라인:

> 공공계약의 이상 징후를, 근거와 함께.

브랜드의 장난스러움이 사건 대상자의 권리나 플랫폼의 정확성을 훼손해서는 안 된다.

## 12. 헌장 변경

다음 변경은 founder 단독 즉시 변경이 아니라 문서화된 검토와 공개 change log가 필요하다.

- AI 자동 공개 허용
- 익명 제보 도입
- 개인 실명 노출 기준 완화
- 수익모델과 편집 분리 원칙 완화
- raw/public 보존 정책 변경
- 공개 점수·순위 도입
- 군사·안보 데이터 범위 확대

변경 제안에는 문제, 대안, 악용 가능성, 법률 의견, migration, rollback을 포함한다.
