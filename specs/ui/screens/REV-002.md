# REV-002 — 독립 Snapshot 검토

상태: **FINAL / REQUIRED COMPLETE**  
Route: `/internal/review/{snapshotId}`  
Surface: `internal`  
Access: `oidc`  
Archetype: `DECISION_REVIEW`  
Test prefix: `rev_002`

## 사용자 목적

불변 snapshot의 공개 preview·claim-evidence-response·diff·gate를 검토해 구조화된 결정을 내린다.

## 이 화면이 즉시 답해야 하는 질문

- 정확히 어떤 snapshot을 검토하는가?
- 각 claim에 충분한 근거·반대근거·소명이 있는가?
- 변경 요청 또는 승인 이유는 무엇인가?

## Above-the-fold 순서

1. `identity`
2. `preview`
3. `matrix`
4. `diff`

1440×900 wide viewport에서 사용자는 스크롤 전에 화면 목적, 객체 상태, 가장 중요한 답, 주요 행동, freshness 또는 blocker를 확인해야 한다.

## 최종 정보 순서

| 순서 | Section ID | 제목 | 구현 Component | 목적 |
|---:|---|---|---|---|
| 1 | `identity` | snapshot | `StructuredContentSection` | hash·version·author·stale. |
| 2 | `preview` | 공개 preview | `DecisionReviewPanel` | exact content. |
| 3 | `matrix` | claim/evidence/response | `KnownUnknownResponse` | coverage. |
| 4 | `diff` | 변경 | `DecisionReviewPanel` | previous review/publication. |
| 5 | `risks` | risk·blocker | `StructuredContentSection` | legal/privacy/source. |
| 6 | `decision` | 결정 | `DecisionReviewPanel` | approve/changes/reject/hold. |

이 순서는 wide, medium, compact에서 의미적으로 동일하다. 화면 폭은 배치를 바꾸지만 중요도를 바꾸지 않는다.

## Layout

- Wide: 12-column internal content; immutable target/diff 8 + criteria/blockers/action 4 sticky
- Medium: 8-column stacked; action follows criteria
- Compact: single column; target summary → blockers → criteria → reason → decision
- Container: `workspace`

## Actions

| Action ID | Label | Interaction | Assurance | Capability | Operation |
|---|---|---|---|---|---|
| `approve` | 승인 | `DESTRUCTIVE_CONFIRMATION` | `STEP_UP` | `review.editorial` | `submitReview` |
| `request-changes` | 변경 요청 | `COMMAND` | `ACTIVE_SESSION` | `review.editorial` | `submitReview` |
| `temporary-restriction` | 임시 공개 제한 | `DESTRUCTIVE_CONFIRMATION` | `STEP_UP` | `review.legal` | `placeTemporaryRestriction` |
| `legal-hold` | 법률 hold 설정 | `DESTRUCTIVE_CONFIRMATION` | `STEP_UP` | `review.legal` | `placeLegalHold` |

Primary action: `request-changes`

## Data contracts

| Operation | API | Method | Path | Request Schema | Response Schema |
|---|---|---|---|---|---|
| `getReviewSnapshot` | `control-api` | `GET` | `/v1/internal/queries/get-review-snapshot` | `getReviewSnapshotQuery` | `ReviewSnapshotResponse` |
| `submitReview` | `control-api` | `POST` | `/v1/internal/commands/submit-review` | `submitReviewRequest` | `submitReviewReceipt` |
| `placeTemporaryRestriction` | `control-api` | `POST` | `/v1/internal/commands/place-temporary-restriction` | `placeTemporaryRestrictionRequest` | `placeTemporaryRestrictionReceipt` |
| `placeLegalHold` | `control-api` | `POST` | `/v1/internal/commands/place-legal-hold` | `placeLegalHoldRequest` | `placeLegalHoldReceipt` |

모든 Submission operation은 raw bearer token을 canonical URL에 남기지 않는다. Magic token은 BFF가 one-time exchange에만 사용하고 이후에는 scoped submission session으로 전환한다.

## Responsive contract

- Compact에서 주요 action과 critical unknown/blocker를 숨기지 않는다.
- Primary table은 의미가 보존되는 record list로 재배치한다.
- Context panel은 drawer 또는 inline section으로 이동하며 focus가 복원된다.
- Horizontal scrolling만으로 핵심 작업을 해결하지 않는다.

## Accessibility contract

- H1은 정확히 하나다.
- Section heading level을 건너뛰지 않는다.
- Keyboard만으로 전체 task를 완료할 수 있다.
- 최소 pointer target은 44×44 CSS px다.
- 상태는 색상에만 의존하지 않는다.
- Dialog/drawer 종료 후 원래 trigger로 focus를 되돌린다.
- Chart가 있으면 같은 사실을 담은 표 또는 문장형 대안을 제공한다.
- Save/submit/session exchange 결과를 적절한 live region으로 알린다.

## Acceptance

- Route와 access mode가 일치한다.
- Section 순서를 바꾸지 않는다.
- 모든 blocking operation을 generated client의 server-only wrapper로 호출한다.
- 모든 필수 상태를 실제 계약으로 구현한다.
- Compact에서 정보와 행동이 소실되지 않는다.
- 권한과 scoped session은 server가 다시 검사한다.
- Screen-specific 금지사항과 global editorial/security policy를 위반하지 않는다.
